📚 Core Concept: Higher-Order Functions without Loops

In ELTE exams, Task 1 strictly tests your ability to query complex nested objects using functional array methods: filter, map, some, every, and reduce.

🔍 Verification (Boolean)
.some(fn): returns true if ≥ 1 item matches.
.every(fn): returns true only if ALL match.
✂️ Transformation & Extraction
.filter(fn): keeps items matching condition.
.map(fn): transforms each item (same length).
.flat(): flattens nested arrays into 1D.
📊 Accumulation
.reduce((acc, x) => acc + x, 0): sum numbers.
.reduce((max, x) => ...): find best object!

Pattern 2: Nested Universal Query

Does every author have at least one book in genre "novel"?

authors.every(author =>
  author.books.some(b => b.genres.includes('novel'))
);
Key logic: Outer check is .every(); inner check is .some() with .includes().
Pattern 3: Finding Best Object with Reduce

Find the author with the highest total page count (return object, not just number).

Click to flip and inspect code.

🔄 Click to flip 
const total = a => a.books.reduce((s, b) => s + b.pages, 0);

const maxAuthor = authors.reduce((max, curr) => {
  return total(curr) > total(max) ? curr : max;
});
// maxAuthor.name
Notice: Do NOT provide 0 as initial value! Without an initial value, max starts as authors[0].
Pattern 4: Flatten & Average Calculation

Calculate the average page count of filtered books rounded to 2 decimals.

Click to flip and inspect code.

🔄 Click to flip 
const allBooks = authors.flatMap(a => a.books);
const filtered = allBooks.filter(b => b.year < 1900 && b.genres.includes('novel'));
const sum = filtered.reduce((s, b) => s + b.pages, 0);
const avg = (sum / filtered.length).toFixed(2);
Trap: .toFixed(2) returns a string (e.g. "412.50"). Use it right before display!

In your actual exam, Task 2 will likely feature a different theme (e.g. pizza order builder, flight ticket baggage calculator, fitness workout timer, or parcel shipping estimator). Do not memorize the book story! Memorize the 4 universal structural pillars below, which every ELTE Task 2 is guaranteed to test.

🎛️ Pillar 1: Event Types & Reading Values Events
1. Range Sliders & Number inputs: Use 'input' (fires live on every drag/keystroke), NOT 'change'. 
const val = Number(slider.value); // ALWAYS wrap in Number()!
2. Select Dropdowns: Use 'change'. Read data attributes from selected option: 
const opt = select.selectedOptions[0];
const pages = Number(opt.dataset.pages); // data-pages
const img = opt.value;                   // value attribute
3. Buttons: Use 'click'.
📋 Pillar 2: Dynamic List & Validation Validation
The 4-Step Validation Flow: 
const val = input.value.trim();
// 1. Empty check
if (val === '') return;
// 2. Limit check
if (list.length >= MAX) return;
// 3. Case-insensitive duplicate check
if (list.some(x => x.toLowerCase() === val.toLowerCase())) return;

// 4. On SUCCESS: add, update DOM, and clear field!
list.push(val);
input.value = ''; // DO NOT clear on error!
if (list.length >= MAX) addBtn.disabled = true;

⚠️ Golden Rule: If the input is invalid/rejected, do NOT clear the input field! The user should not have to retype.

🎨 Pillar 3: Dynamic Styles & Classes DOM UI
1. Style requires units (px, %, etc.): 
bar.style.height = `${minutes}px`;
box.style.width = `${speed * 20}px`;
2. Conditional Class Toggling: 
// classList.toggle(className, booleanCondition)
el.classList.toggle('fast', speed >= 4);

// For multiple elements (NodeList):
document.querySelectorAll('.page').forEach(page => {
  page.classList.toggle('fast', speed >= 4);
});

⚠️ Calling querySelectorAll(...).classList.add() will throw a TypeError! NodeLists require .forEach().

⚖️ Pillar 4: Calculation & Disabling Form Submission
Check Button Workflow: 
// 1. Guard check
if (list.length === 0) {
  status.textContent = 'Add items first!';
  return;
}
// 2. Unrounded comparison
const req = (pages / speed) + (list.length * 5);
if (available >= req) {
  // 3. Format only for string output
  status.textContent = `Fits! (${req.toFixed(2)} min)`;
  // 4. Batch disable inputs on success
  [addBtn, checkBtn, input, select, slider1, slider2].forEach(el => {
    el.disabled = true;
  });
} else {
  status.textContent = `Not enough time! (${req.toFixed(2)} min)`;
  // Inputs remain editable!
}

Flashcard 1

Why must range sliders use the 'input' event instead of 'change'?

Click to flip and check answer.

🔄 Click to flip

'input' fires immediately and continuously on every single pixel of mouse drag or touch movement, updating displays in real-time.

'change' only fires once when the user releases the mouse button!

slider.addEventListener('input', updateVisuals);
Flashcard 2

How do you safely extract data attributes from a <select> dropdown?

Click to flip and check answer.

🔄 Click to flip

In HTML: <option value="x" data-pages="160">

In JS, access the currently active option:

const opt = select.selectedOptions[0];
const pages = Number(opt.dataset.pages);
const title = opt.textContent;
const val = opt.value;
HTML data-my-val becomes JS dataset.myVal (camelCase).
Flashcard 3

What is the danger of comparing with .toFixed(2)?

Click to flip and check answer.

🔄 Click to flip

.toFixed(2) returns a string, not a number!

String comparisons are alphabetical:

"100.00" < "20.00" // evaluates to TRUE! (1 < 2)

Rule: Always perform comparisons on raw numbers, and apply .toFixed(2) only inside the final string interpolation!

Clean, fast to type in an exam, and impossible to forget an element.

    🗺️ Task 3: 2D Grids, Moving Elements & Event Delegation

    Understand the mechanics that students often find hardest: Event Delegation and why `appendChild` moves elements instead of copying them.

    1. The Coordinate Access Trick

    When you create a standard table:

    const cell = table.rows[row].cells[col];

    You don't need querySelectorAll or math indexing! The HTML Table element maintains its own 2D array of rows and cells.

    2. Why `appendChild` MOVES Elements

    DOM nodes can only exist in one position at a time:

    // selectedBook is currently in Cell (0,0)
newCell.appendChild(selectedBook);
// selectedBook is automatically detached from (0,0)
// and attached to newCell!

    No need to call oldCell.removeChild(...) manually!

    3. Event Delegation with `delegate()`

    Instead of adding 20 event listeners to every button and cell:

    delegate(table, '.book', 'click', (event, book) => {
  if (book.closest('.shelf')) return; // ignore books on shelf!
  // selection toggle logic...
});

    One single listener on table handles clicks even as books move across the board.

    4. Live Victory Condition Checking

    Query the DOM directly to know if all books are placed:

    const all = table.querySelectorAll('.book').length;
const shelved = table.querySelectorAll('.shelf .book').length;

if (all === shelved) {
  status.textContent = 'All books are in place!';
}

    No extra state variables needed—the DOM itself is the single source of truth.
